# Picking the ONE Thing

Which thing to do right now is never stored, because it depends on what is blocked, what just opened and what is closing soon. So compute it:

1. **Read the current plan, wherever the user's rhythm keeps it.** The rhythm is named in [PROFILE.md](../../../PROFILE.md#weekly-rhythm), and where its plan lives is the "Plan lives in" line of its entry in [the rhythms reference](../weekly-review/reference/rhythms.md). With no rhythm chosen, read each active domain's Next Up.

   Turn each candidate into the next concrete action that moves it.
2. **Check each candidate's domain** for what actually moved. The plan gives rank; the domain gives what is true.
3. **Weigh, in this order:** closing deadlines and windows first, then whether the next step is in the user's hands, then what is in season (an application round, an exam period, a launch).
4. **Name one.** Not a ranked list.

**Do not rank by score,** if the rhythm keeps scores. A low score flags a starved area worth raising. It does not win the pick.

## When a candidate is not doable

- **Blocked on a person:** the action is the unblock, not the goal. Say so.
- **Blocked by a date:** that candidate sits out. Say so plainly rather than offering the impossible action or inventing a substitute.
- **Already done or overtaken:** propose the replacement rather than reading out a stale line.

## Stay in scope

Only run this when the question is genuinely open. When the conversation is already on a topic, "what should we do now" means within that topic, not a pick across everything.
